## Domain extensions

The [floor plan extension](/diagram/floor-plans) includes straight walls, attached doors and windows,
rooms, dimensions, metric and imperial units, furniture, boundaries, background plans and multiple
floors.

The [restaurant extension](/diagram/restaurant) includes generated table seating, booths, bars,
zones, table numbering, merge and split operations, live statuses, capacity summaries and layout
validation.

Both extensions use the public extension API and can be combined with custom node types, tools,
commands and plugins.

## Production checklist

- Validate documents from APIs, uploads or storage with `parseDiagram` before loading them.
- Decide whether the parent owns state with `v-model` or the diagram owns it with `default-value`.
- Use `select` or `view` mode for users who must not edit the document.
- Persist user-facing operational data deliberately; keep transient statuses outside the document.
- Test keyboard workflows, touch input and application-specific accessible labels.
- Benchmark representative documents and custom nodes; tune routing, collision checks and culling.
- Define server ordering or conflict resolution before applying patches from multiple writers.
- Verify CORS and `foreignObject` behavior for every required export target.

Start with the [installation guide](/diagram/getting-started), then use the
[extension API](/diagram/extensions) for domain-specific behavior.
