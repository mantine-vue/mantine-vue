## Views

Five views are built in: `details`, `list`, `grid`, `gallery` and `tree`. Switching views preserves
the current location, selection, sort and filters. Use `views` to limit or reorder the available
options; see [custom views](/file-manager/customization#custom-views) to add your own.

## Pagination and virtualization

Pagination controls how entries are fetched. Virtualization controls how many loaded rows exist in
the DOM. With the default `virtualize="auto"`, folders above `virtualizeThreshold` render only the
rows near the viewport.

Set `pagination="infinite"` to request another adapter page as the user scrolls:

<Demo data={FileManagerDemos.large} />

`pagination="pages"` displays a pager and requests pages on demand:

<Demo data={FileManagerDemos.pages} />

For partially loaded folders, accurate server-side sorting requires
`capabilities.serverSort`. See [adapter capabilities](/file-manager/adapters#capability-detection).

## Use the headless controller

`useFileManager` returns the controller `FileManager` uses internally. Create it yourself and pass
it through `controller` to add external controls or to build a completely custom interface.
Configure behavioral options such as pagination, upload restrictions and labels in
`useFileManager` when supplying an external controller.

## Undo and redo

Create, rename, move, copy, duplicate and move-to-trash operations can be undone. Overwrites and
permanent deletion cannot be undone. Permanent deletion and emptying the trash clear the history
because earlier steps may reference entries that no longer exist.
