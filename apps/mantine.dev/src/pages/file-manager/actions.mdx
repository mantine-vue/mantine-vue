The toolbar, context menus, compact selection bar and keyboard shortcuts share one action model.
Define an action once, then place it in any of those surfaces.

<Demo data={FileManagerDemos.actions} />

## Create a custom action

```ts
interface FileManagerAction {
  id: string
  label: string | ((context) => string)
  icon?: FileManagerIconName | Component
  color?: string
  shortcutLabel?: string
  visible?: (context) => boolean
  enabled?: (context) => boolean
  run: (context) => void | Promise<unknown>
}
```

The action context contains the target `entries`, the headless `controller`, translated `labels`,
helpers for built-in dialogs in `ui`, and a `scope` of `toolbar`, `item`, `background` or
`selection`. Use `visible` to omit an action and `enabled` to render it disabled.

## Configure action surfaces

Each surface accepts action IDs, inline action objects and the string `divider`. Dividers left at
an edge or beside another divider are removed automatically.

An item in `actions` with a built-in ID overrides that action everywhere. Use `resolveMenu` for a
final context-dependent policy before a surface renders:

```ts
const resolveMenu = (items, context) =>
  context.entries.some((entry) => entry.owner !== currentUser)
    ? items.filter((item) => item.id !== 'delete')
    : items
```

## Built-in action IDs

`open`, `preview`, `back`, `forward`, `up`, `refresh`, `newFolder`, `upload`, `uploadFiles`,
`uploadFolder`, `download`, `rename`, `duplicate`, `cut`, `copy`, `paste`, `moveTo`, `copyTo`,
`favorite`, `delete`, `deletePermanently`, `restore`, `emptyTrash`, `properties`, `undo`, `redo`,
`selectAll` and `clearSelection`.

## Keyboard shortcuts

`shortcuts` maps action IDs to [use-hotkeys](/hooks/use-hotkeys) expressions. It extends the
defaults and replaces duplicate IDs. Set `:shortcuts="false"` to disable all action shortcuts.
They run only while focus is inside the file manager and never while the user is typing in an
input, textarea, select or editable element.
