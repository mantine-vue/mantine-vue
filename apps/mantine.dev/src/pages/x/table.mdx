## Installation

<InstallScript packages="@mantine-vue/table" />

`@mantine-vue/table` builds on Mantine Vue and TanStack Table, which are peer dependencies. Install
them alongside the package:

```bash
npm i @mantine-vue/table @mantine-vue/core @mantine-vue/hooks @mantine-vue/dates \
  @tanstack/vue-table @tanstack/vue-virtual @tanstack/match-sorter-utils \
  @tabler/icons-vue clsx dayjs
```

After installation import package styles at the root of your application:

```ts
import '@mantine-vue/core/styles.css'
// ‼️ import table styles after core package styles
import '@mantine-vue/table/styles.css'
```

Your app must also be wrapped in a [MantineProvider](/theming/mantine-provider).

## Usage

`@mantine-vue/table` is a Vue 3 port of [Mantine React Table](https://www.mantine-react-table.com/),
built on [TanStack Table v8](https://tanstack.com/table/v8). Build a table instance with the
`useMantineVueTable` composable and pass it to the `MantineVueTable` component. Sorting, filtering,
and pagination are enabled by default.

<Demo data={DataTableDemos.usage} />

Pass `data` and `columns` as getters (`get data() { return data.value }`) so the table stays
reactive — `useMantineVueTable` reads its options once, so plain values would be captured as a
snapshot.

## Row selection

Set `enableRowSelection` to render selection checkboxes. Add `enableBatchRowSelection` to allow
selecting a range of rows by holding <kbd>Shift</kbd> while clicking. Read the current selection at
any time with `table.getSelectedRowModel().rows`.

<Demo data={DataTableDemos.rowSelection} />

## Column ordering, pinning, resizing & row ordering

Each feature is an independent `enable*` option. Use the `*Ordering` flags to drag-and-drop columns
or rows. For row ordering the table tracks the drag state (`draggingRow` / `hoveredRow`) but you own
the data, so apply the reorder yourself in `mantineRowDragHandleProps.onDragEnd`.

<Demo data={DataTableDemos.columnOrdering} />

> Use the `*Ordering` flags (`enableColumnOrdering` / `enableRowOrdering`) to reorder. The `*Dragging`
> flags only render a drag handle for custom use and do not track the drop target.

## Editing

`enableEditing` turns on inline editing. Choose how the editor is presented with `editDisplayMode`
(`'cell'`, `'row'`, `'table'`, or `'modal'`) and persist changes in the matching callback.

### Modal editing mode

`editDisplayMode: 'modal'` (the default) opens a dialog with every editable field and Save/Cancel
buttons. Persist the whole row in `onEditingRowSave`, then call `exitEditingMode()`.

<Demo data={DataTableDemos.editing} />

### Cell editing mode

`editDisplayMode: 'cell'` lets a user double-click a single cell to edit it in place. There's no
row-level save callback — persist each change from the column's
`mantineEditTextInputProps.onBlur`.

<Demo data={DataTableDemos.cellEditing} />

### Table editing mode

`editDisplayMode: 'table'` renders every cell as an input at once, so the whole table is editable
without entering an edit mode. Saving works the same way as cell mode (per-cell `onBlur`).

<Demo data={DataTableDemos.tableEditing} />

### Customizing the editing modal

Use the `#editRowModalContent` slot (or `renderEditRowModalContent` option) to replace the modal
body. It receives `internalEditComponents` — the default inputs — which you can lay out freely; drop
in the exported `MVT_EditActionButtons` for wired-up Save/Cancel.

<Demo data={DataTableDemos.editModal} />

## Named slots

Every renderable section can be customized **either** with a Vue named slot on `MantineVueTable`
**or** the equivalent `renderX` option. A named slot takes precedence, and both receive the same
scoped argument. A `#detailPanel` slot also enables the expand column automatically.

<Demo data={DataTableDemos.detailPanel} />

| Named slot                   | Equivalent option                  |
| ---------------------------- | ---------------------------------- |
| `detailPanel`                | `renderDetailPanel`                |
| `rowActions`                 | `renderRowActions`                 |
| `rowActionMenuItems`         | `renderRowActionMenuItems`         |
| `columnActionsMenuItems`     | `renderColumnActionsMenuItems`     |
| `topToolbarCustomActions`    | `renderTopToolbarCustomActions`    |
| `bottomToolbarCustomActions` | `renderBottomToolbarCustomActions` |
| `toolbarInternalActions`     | `renderToolbarInternalActions`     |
| `emptyRowsFallback`          | `renderEmptyRowsFallback`          |

Column-level renderers (`Cell`, `Header`, `Footer`, `Edit`) stay on the column definition.

## Row actions

Set `enableRowActions` to add a dedicated actions column. Provide the buttons with the `#rowActions`
slot (or `renderRowActions` option); use `positionActionsColumn` to place it first or last. For a
built-in overflow menu instead, use the `#rowActionMenuItems` slot.

<Demo data={DataTableDemos.rowActions} />

## Click to copy

Set `enableClickToCopy` on the table or a single column to turn its cells into a button that copies
the cell value to the clipboard on click.

## Column actions

Every column gets a `⋮` actions menu (sorting, hiding, pinning, grouping, …) by default — disable it
per column with `enableColumnActions: false`. Extend the menu with the `#columnActionsMenuItems`
slot: render the built-in `internalColumnMenuItems`, then append your own.

<Demo data={DataTableDemos.columnActions} />

## Row numbers

Set `enableRowNumbers` to prepend a numbers column. `rowNumberDisplayMode: 'static'` numbers rows in
render order, while `'original'` uses each row's index in the original data (stable across sorting
and filtering).

<Demo data={DataTableDemos.rowNumbers} />

## Expanding sub-rows

Set `enableExpanding` and tell the table how to find children with `getSubRows`. Rows that have
sub-rows render an expand toggle; a header toggle expands or collapses all.

<Demo data={DataTableDemos.expanding} />

## Aggregation & grouping

Set `enableGrouping` to let users group by a column (drag it to the grouping zone, or set
`initialState.grouping`). Give a column an `aggregationFn` (`mean`, `sum`, `max`, `count`, …) and an
`AggregatedCell` to summarize each group; use `GroupedCell` to customize the grouped label.

<Demo data={DataTableDemos.aggregation} />

## Column filtering

Column filters are on by default. Pick a filter UI per column with `filterVariant` — `text`,
`select`, `multi-select`, `range`, `range-slider`, `date`, `checkbox`, and more — and enable
`enableColumnFilterModes` to let users switch the match mode (contains, starts with, equals, …).
`enableFacetedValues` auto-populates select options from the data.

<Demo data={DataTableDemos.columnFiltering} />

## Virtualization

For large datasets, set `enableRowVirtualization` (and/or `enableColumnVirtualization`) so only the
visible rows are rendered. Give the scroll container a fixed height via `mantineTableContainerProps`
so the virtualizer can measure the viewport. The demo below renders 10,000 rows.

<Demo data={DataTableDemos.virtualized} />

## Server-side data

For large datasets you typically let the server handle filtering, sorting, and pagination and send
back only the current page. Set `manualFiltering`, `manualPagination`, and `manualSorting` so the
table stops doing those in the browser, provide `rowCount` (the server's real total, used to render
the page count), and control the relevant state with getters plus the matching `onXChange` handlers.
Use the `isLoading` / `showAlertBanner` state for loading and error UI.

The demo below simulates a paginated, sortable, searchable API over a local dataset with a 600 ms
delay — change pages, sort a column, or type in the search box and watch it "re-fetch." Swap
`fakeApi` for a real `fetch('/api/users?...')` call and it works unchanged.

<Demo data={DataTableDemos.serverSide} />

> Pass `data`, `rowCount`, and each controlled `state` slice as **getters** — the table reads its
> options once, so getters are what keep server-driven values (like the `rowCount` total and the
> current page) reactive.

## Server-side grouping

Use server-side grouping for hierarchical views over large datasets. Groups load lazily: root groups load first, child groups load when expanded, and records load after the final grouping level.

Each level manages its own pagination, sorting, filtering, loading, and error state.

Enable the feature with the `serverGrouping` table option and create a provider with `createServerGroupingProvider`. The provider handles backend requests through `loadGroups` and `loadRecords`, while adapter functions such as `groups`, `groupId`, `groupLabel`, and `records` map your API response into the table's internal model.

```ts
const provider = createServerGroupingProvider({
  loadGroups: async (ctx) => {
    // Fetch grouped data from your API
  },
  loadRecords: async (ctx) => {
    // Fetch final records from your API
  },
})
```

The example below starts grouped by region and sales rep:

```ts
serverGrouping: {
  provider,
  defaultGrouping: ['region', 'rep'],
}
```

<Demo data={DataTableDemos.serverGrouping} />

### Grouping controls

When grouping uses the table's `grouping` state, a **Group by** control is available in the top toolbar. Users can add, remove, reorder, or clear grouping levels.

By default, columns are groupable when they are data columns and `enableGrouping` is not `false`. Use `groupBy.columns` to explicitly define available grouping fields, including custom descriptors such as `createdAt:month`.

```ts
serverGrouping: {
  groupBy: {
    enabled: true,
    allowReorder: true,
    allowClearAll: true,
    columns: ['region', 'rep', 'createdAt:month'],
    getFieldLabel: (field) => labels[field],
    renderControl: (ctx) => /* custom control */,
    mantineButtonProps: {},
    mantineMenuProps: {},
    mantinePillProps: ({ field }) => ({}),
  },
}
```

The `#serverGroupByControl` slot can also replace the default control and takes precedence over `renderControl`. It receives:

```ts
{
  grouping,
  groupableColumns,
  addGroup,
  removeGroup,
  moveGroup,
  clearGrouping,
  table,
}
```

Column action menus also expose grouping actions. Disable them with:

```ts
serverGrouping: {
  groupBy: {
    showInColumnActions: false,
  },
}
```

`defaultGrouping` sets the initial hierarchy for uncontrolled tables. Controlled `state.grouping` and `initialState.grouping` take precedence.

If no grouping is configured, records load directly from the provider and the table behaves as a normal server-side table.

### Pagination, sorting, and filtering

The root level uses the table's regular pagination UI. Nested levels use independent pagination.

```ts
serverGrouping: {
  initialPageSize: 15,
  pagination: {
    showForGroups: true,
    showForRecords: true,
    showAtRoot: false,
    mantineActionIconProps: {},
  },
}
```

`initialPageSize` also sets the fixed page size used by nested levels.

Sorting, global filters, and column filters are forwarded to the provider in grouped and ungrouped modes. Use `sortingMode` and `filteringMode` to control whether state is shared across levels.

Changing filters resets the root to the first page and reloads affected levels.

### Provider context and state

Grouping fields are opaque strings. Values such as `createdAt:month` are passed to the provider unchanged, so your backend decides how to interpret them.

If child requests depend on `parentGroups[n].value`, map `groupValue` to the backend value your loader expects. Otherwise, use `parentGroup.id` or `parentGroup.meta`.

Each provider request receives:

```ts
{
  parentGroups,
  pagination,
  sorting,
  columnFilters,
  globalFilter,
  signal,
}
```

Forward the provided `AbortSignal` to your HTTP client so obsolete requests can be cancelled automatically.

Expansion can be controlled with:

```ts
state.serverGroupingExpanded
onServerGroupingExpandedChange
```

Per-path state and reloading are available through:

```ts
table.setServerGroupingPagination(...)
table.setServerGroupingSorting(...)
table.setServerGroupingColumnFilters(...)
table.setServerGroupingGlobalFilter(...)

table.reloadServerGrouping()
table.reloadServerGroupingPath(pathId)
```

Customize grouped rendering with the following slots or their equivalent `renderGroup*` options:

```ts
#serverGroupLabel
#serverGroupCount
#serverGroupCell
#serverGroupError
#serverGroupEmpty
#serverGroupLoading
```

### Row selection

`enableRowSelection` works with server-side grouping. Selection applies to record rows only; group rows do not render selection checkboxes.

The header checkbox operates on loaded records inside expanded groups. Records in collapsed or unloaded groups are not implicitly selected.

By default, collapsing a group preserves its selected records. To clear them on collapse:

```ts
serverGrouping: {
  selection: {
    clearOnCollapse: true,
  },
}
```

For bulk actions across the full filtered dataset, enable **Select all matching records**:

```ts
serverGrouping: {
  selection: {
    enableSelectAllMatching: true,
  },
}
```

The default `selectAllMode: 'query'` stores the selection as a query instead of downloading every matching row id.

```ts
const payload = table.getServerGroupingSelectionPayload()

await api.bulkArchive(payload)
```

Unchecking an individual row while query selection is active adds that row to the exclusion set. Changing the grouping or shared filters clears the query selection because it refers to the previous result set.

For small bounded datasets, use explicit ids instead:

```ts
serverGrouping: {
  selection: {
    enableSelectAllMatching: true,
    selectAllMode: 'ids',
    loadAllMatchingRowIds,
  },
}
```

<Demo data={DataTableDemos.serverGroupingSelection} />

Selection APIs are also available programmatically:

```ts
table.getServerGroupingSelectionSummary()
table.toggleAllServerGroupingRecordsSelected(value?)
table.selectAllMatchingServerGroupingRecords()
```

### TanStack Query

If your app already uses [TanStack Query](https://tanstack.com/query/latest), use it for caching and request deduplication instead of the optional `serverGrouping.cache`.

Provider loaders are regular async functions, so they can delegate to `queryClient.fetchQuery`. Build the query key from the provider request context.

After invalidating cached data, reload the table:

```ts
await queryClient.invalidateQueries(...)
table.reloadServerGrouping()
```

## Localization

The English locale ships by default. Pass a custom `localization` (a partial object is merged over
English):

```ts
import { MVT_Localization_EN } from '@mantine-vue/table/locales/en'

useMantineVueTable<Person>({
  get columns() {
    return columns
  },
  get data() {
    return data.value
  },
  localization: { ...MVT_Localization_EN, actions: 'Options' },
})
```
