# Mantine WhatsApp inbox

[![npm](https://img.shields.io/npm/dm/@mantine-vue/whatsapp-inbox)](https://www.npmjs.com/package/@mantine-vue/whatsapp-inbox)

`@mantine-vue/whatsapp-inbox` provides a WhatsApp-style messaging experience: conversation
browsing, message history, a capability-driven composer, approved templates, interactive messages
and media – as a full-page inbox, a modal or a drawer.

## Installation

<InstallScript packages="@mantine-vue/whatsapp-inbox" />

After installation, import package styles at the root of your application:

```ts
import '@mantine-vue/core/styles.css'
// ⚠️ import whatsapp-inbox styles after core package styles
import '@mantine-vue/whatsapp-inbox/styles.css'
```

## The package is a UI toolkit

The extension renders application data and emits user actions. It does not fetch data, upload
files, open sockets, or communicate with Meta.

to implement and no client to configure.

## Data flows in one direction

```
your backend ──▶ normalized props ──▶ components ──▶ typed events ──▶ your backend
```

1. Map whatever your backend returns onto the [domain model](/whatsapp-inbox/types).
2. Pass it down as props.
3. Answer the emitted events, then push the new data back in as props.

Because the components hold no copy of your data, a message that changes on the server is
reflected the moment the prop changes – there is no internal cache to invalidate. See
[backend integration](/whatsapp-inbox/integration) for TanStack Query and WebSocket examples.

## Non-goals

The extension does not connect to Meta's WhatsApp API, authenticate, make requests, or decide
whether the 24-hour window is open. It assumes no CRM, provider, database, or server framework.
