## Backend neutral by construction

Nothing in the domain model mirrors a Meta Cloud API response. Your application maps whatever its
backend returns onto these types, which is what keeps the components independent of any particular
WhatsApp provider, CRM or transport.

Timestamps are plain values so any serialization survives the trip: ISO 8601 strings are
recommended, but anything `new Date(value)` understands is accepted.

```ts
type WhatsAppTimestamp = string | number | Date
```

## Messages

`WhatsAppMessageData` is a discriminated union on `type`. Narrowing gives access to exactly the
payload that type carries, and adding a member is a compile error in every renderer that must
handle it.

```ts
interface WhatsAppMessageBase {
  id: string
  conversationId?: string
  direction: 'inbound' | 'outbound'
  status?: WhatsAppDeliveryStatus
  timestamp: WhatsAppTimestamp
  author?: { id?: string; name: string; avatarUrl?: string }
  replyTo?: WhatsAppMessageReference
  error?: { code?: string; message?: string; retryable?: boolean }
  reactions?: { emoji: string; count?: number; reacted?: boolean }[]
  forwarded?: boolean
  /** Anything you need to carry along. Never read by the components. */
  meta?: Record<string, unknown>
}

type WhatsAppMessageData =
  | (WhatsAppMessageBase & { type: 'text'; text: string })
  | (WhatsAppMessageBase & { type: 'image'; attachment: WhatsAppAttachment; caption?: string })
  | (WhatsAppMessageBase & { type: 'video'; attachment: WhatsAppAttachment; caption?: string })
  | (WhatsAppMessageBase & { type: 'audio'; attachment: WhatsAppAttachment; caption?: string })
  | (WhatsAppMessageBase & { type: 'document'; attachment: WhatsAppAttachment; caption?: string })
  | (WhatsAppMessageBase & { type: 'sticker'; attachment: WhatsAppAttachment; caption?: string })
  | (WhatsAppMessageBase & { type: 'template'; template: WhatsAppTemplateInstance })
  | (WhatsAppMessageBase & {
      type: 'interactive'
      interactive: WhatsAppInteractiveContent
      reply?: { id: string; title?: string }
    })
  | (WhatsAppMessageBase & { type: 'location'; location: WhatsAppLocation })
  | (WhatsAppMessageBase & { type: 'contacts'; contacts: WhatsAppContactCard[] })
  | (WhatsAppMessageBase & { type: 'system'; text: string })
  | (WhatsAppMessageBase & { type: 'unsupported'; text?: string })

type WhatsAppDeliveryStatus = 'pending' | 'sent' | 'delivered' | 'read' | 'failed'
```

`meta` is the extension point for message types of your own: put your discriminator there and pick
it up in `renderMessage`.

## Conversations and contacts

```ts
interface WhatsAppConversationSummary {
  id: string
  contact: WhatsAppContact
  lastMessage?: WhatsAppConversationPreview
  unreadCount?: number
  updatedAt?: WhatsAppTimestamp
  status?: string
  assignee?: { id: string; name: string; avatarUrl?: string }
  pinned?: boolean
  muted?: boolean
  labels?: { id: string; name: string; color?: string }[]
  meta?: Record<string, unknown>
}

/** The opened conversation: a summary plus what may be sent in it. */
interface WhatsAppConversationData extends WhatsAppConversationSummary {
  capabilities?: WhatsAppConversationCapabilities
}

interface WhatsAppContact {
  id: string
  name?: string
  phoneNumber?: string
  avatarUrl?: string
  about?: string
  email?: string
  tags?: string[]
  fields?: { key: string; label: string; value: string; href?: string }[]
  meta?: Record<string, unknown>
}
```

`status` is an open union: `'open' | 'pending' | 'resolved' | 'snoozed' | 'archived'` autocompletes
but any string is accepted, because workflow states belong to your product.

## Capabilities and the messaging window

```ts
interface WhatsAppConversationCapabilities {
  /** @default true */
  canSendFreeForm?: boolean
  /** @default false */
  canSendTemplates?: boolean
  /** @default false */
  canSendMedia?: boolean
  /** @default false */
  canSendInteractive?: boolean
  /** @default false */
  canUseEmoji?: boolean
  /** @default false */
  canReplyToMessage?: boolean
  /** @default true */
  canRetryFailed?: boolean
  allowedMediaTypes?: WhatsAppMediaType[]
  interactiveTypes?: ('button' | 'cta_url' | 'list')[]
  maxTextLength?: number
  mediaConstraints?: Partial<Record<WhatsAppMediaType, WhatsAppMediaConstraints>>
  messagingWindow?: WhatsAppMessagingWindow
  disabledReason?: string
}

interface WhatsAppMessagingWindow {
  /** @default 'unknown' */
  state: 'open' | 'closed' | 'unknown'
  reasonCode?: string
  reason?: string
  expiresAt?: WhatsAppTimestamp
}
```

`resolveCapabilities()` fills in the defaults and returns a `WhatsAppResolvedCapabilities` with
every flag present, plus `windowClosed` and `canSendAnything`. It is what the composer reads, and
it is exported so your own code can apply the same rules.

## Templates

```ts
interface WhatsAppTemplate {
  id: string
  name: string
  language: string
  languageLabel?: string
  category?: 'marketing' | 'utility' | 'authentication' | (string & {})
  status?: 'approved' | 'pending' | 'rejected' | 'paused' | 'disabled' | (string & {})
  components: WhatsAppTemplateComponent[]
  description?: string
}

type WhatsAppTemplateComponent =
  | {
      type: 'header'
      format?: 'text' | 'image' | 'video' | 'document' | 'location'
      text?: string
      parameters?: WhatsAppTemplateParameter[]
      example?: WhatsAppAttachment
    }
  | { type: 'body'; text: string; parameters?: WhatsAppTemplateParameter[] }
  | { type: 'footer'; text: string }
  | { type: 'buttons'; buttons: WhatsAppTemplateButton[] }

interface WhatsAppTemplateParameter {
  key: string
  label?: string
  type?: 'text' | 'currency' | 'date_time' | 'image' | 'video' | 'document' | 'location'
  required?: boolean
  example?: string
  description?: string
  placeholder?: string
  maxLength?: number
}

interface WhatsAppTemplateValues {
  header?: Record<string, string>
  body?: Record<string, string>
  /** Keyed by button index, then by parameter key */
  buttons?: Record<string, Record<string, string>>
  headerMedia?: WhatsAppAttachment | null
}
```

## Outgoing payloads

Everything the composer can ask you to send, as a discriminated union on `kind`.

```ts
interface WhatsAppOutgoingMessageBase {
  conversationId: string
  /** Generated by the composer, for reconciling the optimistic message */
  clientId: string
  replyTo?: string
}

type WhatsAppOutgoingMessage =
  | (WhatsAppOutgoingMessageBase & { kind: 'text'; text: string })
  | (WhatsAppOutgoingMessageBase & {
      kind: 'media'
      attachments: WhatsAppAttachment[]
      caption?: string
    })
  | (WhatsAppOutgoingMessageBase & {
      kind: 'template'
      templateId?: string
      name: string
      language: string
      values: WhatsAppTemplateValues
      template: WhatsAppTemplate
    })
  | (WhatsAppOutgoingMessageBase & { kind: 'interactive'; interactive: WhatsAppInteractiveContent })
```
