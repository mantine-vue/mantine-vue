## Usage

`Cascader` lets users select a value from hierarchical data by drilling down through
cascading columns. Picking an option in one column reveals its children in the next column.
The value is an ordered path from the root option to the selected node, for example
`['asia', 'jp', 'tokyo']`.

All demos on this page switch to the [flat list layout](#flat-list-layout) on small screens.
Open them on a larger screen to test cascading columns, hover expansion, and column keyboard
navigation.

<Demo data={CascaderDemos.usage} />

## Data prop

Data passed to `data` is an array of `CascaderOption` objects:

- Each option must have a unique `value` across the whole tree
- `label` is optional; `value` is used when it is not set
- `children` contains nested options
- `disabled` prevents an option from being selected or expanded

```ts
import type { CascaderOption } from '@mantine-vue/core'

const data: CascaderOption[] = [
  {
    value: 'asia',
    label: 'Asia',
    children: [
      {
        value: 'jp',
        label: 'Japan',
        children: [{ value: 'tokyo', label: 'Tokyo' }],
      },
    ],
  },
]
```

## Value and change event

`Cascader` value is an ordered array of option values, or `null` when nothing is selected.
Use `v-model` to control it. The `change` event receives the selected path and the resolved
chain of `CascaderOption` objects:

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { Cascader } from '@mantine-vue/core'
import type { CascaderOption } from '@mantine-vue/core'

const value = ref<string[] | null>(['europe', 'fr', 'paris'])

function handleChange(path: string[] | null, options: CascaderOption[]) {
  console.log(path, options)
}
</script>

<template>
  <Cascader v-model="value" :data="data" @change="handleChange" />
</template>
```

By default, only leaf options can be selected. Clicking a parent expands the next column.

## Flat list layout

Set `withColumns` to `false` to render a flat list of full paths. This works well on narrow
screens:

<Demo data={CascaderDemos.flatList} />

Use [useMediaQuery](/hooks/use-media-query/) to switch layouts responsively:

```vue
<script setup lang="ts">
import { Cascader } from '@mantine-vue/core'
import { useMediaQuery } from '@mantine-vue/hooks'

const withColumns = useMediaQuery('(min-width: 48em)')
</script>

<template>
  <Cascader :with-columns="withColumns" :data="data" />
</template>
```

## Controlled search value

Use `searchValue` and the `searchChange` event to control the search value:

```vue
<Cascader
  searchable
  :data="data"
  :search-value="searchValue"
  @search-change="searchValue = $event"
/>
```

## Named slots

Every Cascader prop that accepts renderable content also has an idiomatic Vue named slot.
The existing prop API remains supported and takes precedence when both are provided:

```vue
<Cascader :data="data" searchable>
  <template #renderOption="{ option, level }">
    <span>Level {{ level + 1 }}: {{ option.label }}</span>
  </template>
  <template #renderSearchOption="{ query, options }">
    <span>{{ query }}: {{ options.map((option) => option.label).join(' / ') }}</span>
  </template>
  <template #separator>→</template>
  <template #nothingFoundMessage>No matching paths</template>
</Cascader>
```

The `label`, `description`, `error`, `leftSection`, and `rightSection` input slots are forwarded.
`nothingFound` is supported as an alias for `nothingFoundMessage`.
